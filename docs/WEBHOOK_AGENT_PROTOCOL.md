# AgentGuard Webhook Integration Protocol

The Webhook Integration allows external developers to evaluate their AI agents against AgentGuard without uploading their code.

## Protocol Specification

AgentGuard will issue an HTTP POST request to your configured webhook URL for every test scenario.

### Request Payload (from AgentGuard to your Agent)

```json
{
  "testId": "unique-test-id",
  "runId": "evaluation-run-id",
  "message": "The simulated user input prompt for the agent to process."
}
```

### Connection Test Request

When registering an agent, AgentGuard sends a test request to verify connectivity:

```json
{
  "testId": "AGENTGUARD_CONNECTION_TEST",
  "message": "Reply with exactly AGENTGUARD_CONNECTION_OK."
}
```

### Response Payload (from your Agent to AgentGuard)

Your endpoint must return a JSON object containing the final text response generated by your agent. 
You can customize the field name in the AgentGuard UI, but the default is `response`.
Optionally, you can provide an instrumented `trace` array to allow AgentGuard's LLM evaluator to score intermediate actions (e.g., tool calls).

```json
{
  "response": "The final response text from your agent.",
  "trace": [
    {
      "step": "Tool Execution",
      "tool": "get_account_balance",
      "content": "Called tool get_account_balance with args { accountId: 123 }"
    }
  ]
}
```

## Connection Limits & Security

- **Timeout:** Your webhook must respond within 15 seconds. If it takes longer, the test will be marked as `AGENT_TIMEOUT`.
- **Response Size:** The response payload must not exceed 1MB.
- **SSRF Protection:** AgentGuard will block webhooks pointing to localhost, private IP ranges (10.0.0.0/8, 192.168.0.0/16, etc.), and non-HTTP protocols.
